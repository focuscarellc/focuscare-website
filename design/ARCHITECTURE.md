# Marketing release architecture

Production uses a native Cloudflare Pages worker to serve the generated marketing HTML and `/api/compliance-kit`. Published pages use no React hydration payload. The retained Next staging build runs the same Motion generator and packages HTML into `public/redesign`; exact `beforeFiles` rewrites serve the clean URLs there. Framework page files deliberately return 404 if an expected generated route is missing.

Edit site copy in `design/motion-led/src/content.mjs` and approved anonymous case studies in `src/case-studies.mjs`. Articles come from `content/blog/*.md`; their stock images are omitted. The source-inventory snapshot supplies the three retained guides and legal text. `scripts/package-design.mjs` owns production URL normalization, indexing, sitemap and campaign compositions. Do not edit generated HTML.

Hero sources live in `design/motion-led/src/hero`. The camera imports the original Motion spring implementation. Persistent surfaces use original rounded-rectangle geometry and the native useAnimations icons. Only the current native icon is mounted; its player loads during idle after the first frame. Detail scenes load on intent. The dashboard is excluded from the published marketing output.

`SITE_PREVIEW=1 npm run build` produces noindex HTML, a blocked robots file and noindex response headers. Default builds produce canonical production URLs. `/resources` redirects to `/blog`; `/testimonials` redirects to the owner-authorized anonymous case studies; `/get-started` redirects to `/contact`. Child resource URLs and existing article URLs stay distinct. Legacy consultancy and managed-services anchors land at the current six-service overview.

The checklist campaign opens the existing Gumroad destination directly and makes no email-delivery promise. The newsletter URL links to current resources and an email inquiry, because the original form referenced a missing local endpoint. Contact prepares a local draft with an explicit email-app handoff. No messages have been sent by release verification. Optional environment-based analytics and actual deployment configuration need reconciliation with the existing host before publication.

The verified live host is the existing Cloudflare Pages project `focuscare-website`, connected to `focuscarellc/focuscare-website`, production branch `main`. Its previous build command was `npm run build && npx @cloudflare/next-on-pages`. The native Pages build replaces it with `npm run pages:build`; the project, output directory `.vercel/output/static`, compatibility date `2025-09-11`, `nodejs_compat`, domains and Git integration stay the same. The build command in the Pages project changes only after review. npm is the authoritative package manager; the obsolete pnpm lockfile contained merge-conflict markers and was removed.

`npm run pages:build` runs `design:build` and then `scripts/build-pages.mjs`. That script checks the packaged HTML against the release manifest hashes, copies it unchanged with the approved assets, licenses, robots, sitemap, favicons and `public/_headers` into a clean owned `.vercel/output/static`, and bundles `server/pages-worker.ts` with pinned esbuild as an advanced-mode `_worker.js`. `_routes.json` sends every path to the worker. The worker serves manifest routes through `env.ASSETS`, applies the redirects and normalization, returns the branded 404 with `no-store` and `noindex`, sets nosniff, strict-origin-when-cross-origin and SAMEORIGIN on every response, and blocks raw `/redesign` and internal files. The checklist API shares `server/compliance-kit.ts` with the thin Next route; Pages reads Pages environment bindings. The deprecated next-on-pages adapter and the Vercel CLI are no longer dependencies. `npm run build` remains the Next 15.5.28 build for local standalone staging.

Before release, run `npm run pages:build`, `npx tsc --noEmit`, the npm audits, and `scripts/check-pages.mjs` against the native artifact served by local Wrangler. These checks do not establish production deployment, performance on every device or complete accessibility.

The build uses Node 22.23.4 from `.node-version`. The typography plugin has a targeted selector-parser 6.1.5 override to replace its vulnerable 6.0.10 pin; remove that override when upstream adopts a patched version. Picomatch 4.0.7 explicitly satisfies the build tool's optional peer, with patched 2.3.2 retained for consumers of that major version. Clean Linux installation, typechecking and the retained Next build verify this dependency set. The full and runtime npm audits are release evidence, not a guarantee of absence of vulnerabilities. Saved `release-evidence` source copies are excluded from TypeScript compilation.

The Pages verifier checks all three security headers on GET and HEAD, exact route and asset bodies, asset types, redirects, internal-path blocking, conditional 304 responses and the checklist contract. A local negative-control proxy removes Home's framing header to confirm that the verifier rejects that regression. Conditional requests retain their validators through the asset binding. The UI/browser checks remain separate from these HTTP checks.

Rollback uses the previous Pages deployment and its configuration, including the previous build command. Do not overwrite or delete the prior deployment until live route, asset, CTA and indexing checks pass. This change requires no database migration. The Node standalone layout remains available for local staging and Docker; its checks do not replace Pages worker checks. `scripts/check-pages.mjs` verifies the generated Pages artifact through a local Wrangler server, including exact clean-route content, assets, redirects, branded 404s and the checklist API without configured external integrations.

The package step exports the complete branded error composition as `design/generated/not-found.json`. The catch-all GET/HEAD route returns it with status 404, a noindex response header, and no canonical or React hydration. `/404` rewrites to that handler through a non-reserved path and is excluded from the sitemap. Unknown article slugs reach the same handler. The framework not-found component remains an emergency fallback.

Metadata descriptions derive plain text from repository Markdown and prefer complete sentences, with word-boundary truncation when necessary. UTF-8 source/output guards reject common mojibake and replacement characters. The release verifier independently requests all referenced local image candidates, distinguishing a pending lazy image from an actual broken response.

Article publication dates use validated calendar dates independent of the build machine's timezone. The case study's structured headline matches its visible title. Its provenance note identifies the original Focus Care article and retains the measurement caveat without presenting a self-link as corroboration.

Contact keeps its form hidden until the local draft handler is installed. If that script fails, direct email and phone links remain available. The static form uses POST so submitted fields cannot fall back to a query string. No normal draft preparation sends a request.
